They use the `chrome.devtools` part of the fake in [`../fakes/`](../fakes/) and stub `globalThis.fetch` for the platform's chain API.

## How it works

`ad-network-panel.test.ts` loads [`panel.html`](../../src/devtools/ad-network/panel.html), keeps its `<body>` without `<script>` tags, and puts it in the document. It stores `nsm.test` as an enabled site, sets `fakeChrome.devtools.inspectedWindow.evalHandler` so `location.origin` returns the origin a test navigated to, and stubs `fetch` so every method resolves as "Resolved" in "Cat" (recording each URL asked). It feeds HAR entries through `fakeChrome.devtools.network.onRequestFinished.dispatch()` and navigations through `onNavigated.dispatch()`, then waits on the panel's `ready` promise. What the panel ran in the page is read from `fakeChrome.devtools.inspectedWindow.evaluated`. `afterAll` calls `panel.stop()` and restores `fetch`.

`api.test.ts` builds a new `InspectedSite`, `MethodCache` and `MethodResolver` in each test, so nothing carries over. Its `evalHandler` answers `location.origin` and the token scan from a `page` object the test changes.

Asynchronous results are awaited with `waitFor()` from [`../wait.ts`](../wait.ts); fixed sleeps appear only where a test shows that nothing happens.

## Conventions

- Panel assertions read text, class names and counts only, never elements (see [`../README.md`](../README.md)).
- Tests that start a class (`AdNetworkPanel`, `PdInspectorPanel`, `PanelRegistrar`, `ResolveQueue`) stop it in `afterAll`/`afterEach`, so no listener or timer outlives the file.
- `pending-capture.test.ts` restores the window's `fetch` and `XMLHttpRequest.prototype` methods and deletes the page global after each test.
