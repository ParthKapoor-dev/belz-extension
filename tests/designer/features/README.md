## How it works

- `variables.test.ts` runs the real CodeMirror completion source: it builds an `EditorState` and a `CompletionContext` at the `|` in a test string, and reduces the result to plain labels and offsets.
- `modal-escape.test.ts` opens the real modals, CodeMirror included, in happy-dom, and presses Esc at the focused element. It reads the IDE's `view` to know whether it is open. The completion list does not open under happy-dom, so only the search panel is used to show that CodeMirror's own popups get Esc first.
- `autofill.test.ts` joins three worlds with the fake: `fakeChrome.runtime.respond` passes the page's message to a real `MessageRelay`, with a `contentScriptSender()` for the page's current URL. It moves the page with `history.replaceState`, renders inputs from the [`ad-inputs` fixture](../../fixtures/ad-inputs.ts), and changes `document.title` to let the fill start.
- `shortcuts.test.ts` builds the AD and PD `KeyboardShortcuts` once, starts the AD one before each test on a body with an `<exp-button id="runTest">` and an input, and stops both after.
- Fixture-based tests re-render the page in each test or `beforeEach`, since all files share one document.
- Waits use `waitFor()` from [`../../wait.ts`](../../wait.ts); fixed sleeps only show that nothing happens.

## Conventions

- Extracted inputs hold live DOM nodes (`testValueElement`, `container`). `json-editor.test.ts` maps them to a plain `summary()` before any assertion. Do the same for any new test on DOM-holding results.
- A test that locks `modalLock` must unlock it before it ends. `modal-escape.test.ts` disposes every modal it opened in `afterEach`.

## Adding or changing things

**Testing a new feature:** add `<feature>.test.ts` here. Keep the feature's logic in importable modules (as `json-editor/values.ts` and `ide/language.ts` are), and test those rather than the class that wires listeners. If the feature reads AD page markup, add or extend a fixture in [`../../fixtures/`](../../fixtures/).
